6. ライセンス（重要・注意点あり）
Common Public Attribution License (CPAL) 1.0
OSI承認のオープンソースライセンス（2007年承認）
Mozilla Public License 1.1 ベース＋帰属要件追加
CPAL の特徴（要注意）
帰属表示義務: 実行時に**「Original Developer の Attribution Information を GUI に目立つ形で表示」**することが必須
External Deployment 条項: ネットワーク経由で提供する場合もソースコード開示が必要
これは AGPL（Affero GPL）に類似した「SaaSロックイン回避」条項
改変版を社内SaaSやクラウドで提供してもソース公開義務
商用利用上の含意
✅ 企業内でそのまま使うのは自由
✅ デスクトップアプリとして配布することも可能
⚠️ 改変して社内SaaS化する場合 → ソースコード開示義務
⚠️ 改変して有償SaaS提供する場合 → ソース開示 + 帰属表示必須
→ Microsoft Project のように完全にプロプラ化して再販売は不可。BSD/MIT のような自由度はない。

MPL 2.0	❌	❌	改変ソース開示
CPAL 1.0	✅	✅	改変SaaS開示
AGPL 3.0	❌	✅	強コピーレフト

結論先出し
できます。以下を提案:

コア共通: TypeScript フロント + Rust/WASM PMBOK計算エンジン + JSON Schema 標準ファイル形式
Pattern A（完全ローカル）: Tauri 2.0 + SQLite（バイナリ10〜20MB、Mac/Win/Linux）
Pattern B（AWS最安）: CloudFront + S3 + HTTP API Gateway + Lambda + DynamoDB + S3（50ユーザで月 $5前後）

1. 全体方針（重要な意思決定）
A. ファイル形式は「中立な JSON Schema」を独自定義
MPP / XML 互換は副次的に対応（インポート/エクスポート用）
中身は JSON ベース（人間可読、Git-friendly、AI が直接編集しやすい）
MCP からも直接読み書き可能な開放性
{
  "project": {
    "id": "uuid",
    "name": "Site renewal",
    "startDate": "2026-06-01",
    "calendar": "JP-business",
    "tasks": [
      {"id":"t1","name":"要件定義","duration":10,"predecessors":[]},
      {"id":"t2","name":"設計","duration":15,"predecessors":["t1"]}
    ],
    "resources": [...],
    "assignments": [...],
    "baselines": [],
    "version": 1
  }
}
B. コア計算は Rust → WASM
CPM / Forward-Backward Pass / Resource Leveling / EVM / CPI / SPI
ブラウザでも Tauri でも Lambda でも完全に同じ実装を使う
WASM 化することで Lambda の cold start も速い（ms単位）
C. AI は完全に外部
MCP Server（標準プロトコル、Claude Code 等から叩ける）
REST API（汎用、自社アプリも繋げる）
本体プロダクトは「AI連携設定」UI だけ持つ（OFF時は完全に非依存）
